# UI Coding Standards

This document is the single source of truth for how UI is built in this project. It applies to every page, layout, and component under `src/app/` and `src/components/`.

## The rule: shadcn/ui only, zero custom components

**Every piece of UI in this project must be a [shadcn/ui](https://ui.shadcn.com) component. Zero custom components are to be created.**

- Do not hand-write a new component in `src/components/` (or anywhere else) from scratch — no bespoke `Card`, `Modal`, `Badge`, `Tabs`, etc. built from raw `<div>`s and Tailwind classes.
- Do not wrap a shadcn component in a new "custom" component just to change a class or a default prop. Compose shadcn primitives directly at the call site instead.
- Do not reach for another component library (MUI, Chakra, Ant Design, Headless UI, Radix used directly, react-bootstrap, etc.). shadcn is the only UI layer this project uses.
- Raw HTML elements (`div`, `span`, layout wrappers) are fine for structure/layout, but any interactive or stylable UI primitive (button, input, dialog, dropdown, card, table, form field, etc.) must come from shadcn.

If a screen needs a UI primitive that doesn't exist yet in `src/components/ui/`, **add it via the shadcn CLI** — don't write it by hand:

```bash
npx shadcn@latest add <component-name>
```

This project is already configured for this (`components.json`, style `base-nova`, base color `neutral`, icon library `lucide`). Running the CLI generates the component into `src/components/ui/` following shadcn's own conventions, wired up to the existing design tokens in `src/app/globals.css`.

## Where components live

- `src/components/ui/` — components generated by the shadcn CLI. This is the *only* place UI primitives should be defined. Everything currently here (`button.tsx`, `popover.tsx`, `calendar.tsx`, `dialog.tsx`) was added this way; new primitives must follow the same path.
- `src/app/**` — pages and layouts compose shadcn components from `@/components/ui/*` directly. Do not introduce a `src/components/` (non-`ui`) tree of app-specific wrapper components.

## Composition over custom components

When a screen needs something that looks like a "new" component (e.g. a stat card, a workout row, a settings section), build it by composing existing shadcn primitives inline in the page/route file, using Tailwind utility classes for layout. Do not extract it into a new custom component just because the markup is reused — reuse shadcn components and Tailwind classes instead of inventing new abstractions.

If a composition is used identically in more than one place, prefer duplicating the shadcn composition over creating a custom wrapper component. If duplication becomes unmanageable, raise it explicitly rather than silently introducing a custom component.

## Styling

- Use Tailwind utility classes for layout and spacing between shadcn components. Do not write new CSS files or `<style>` blocks.
- Use the `cn()` helper from `@/lib/utils` (shadcn's standard utility) to merge conditional classes — this already exists in the project and is what shadcn-generated components use internally.
- Do not override shadcn component internals by editing the generated files in `src/components/ui/` beyond what the shadcn CLI itself produces or updates. If a variant is needed, use the component's own `variant`/`size` props (via `class-variance-authority`, already a dependency) rather than hand-editing styles.
- Icons come from `lucide-react` only (the configured `iconLibrary` in `components.json`), consistent with shadcn's icon choice.

## Adding a new shadcn component

1. Check `src/components/ui/` first — the primitive may already exist.
2. If it doesn't, run `npx shadcn@latest add <component-name>` to generate it.
3. Commit the generated file(s) as-is. Do not modify generated component internals beyond what the CLI produced, aside from accepting CLI-driven updates (`npx shadcn@latest diff` / `update`).
4. Import and compose it from `@/components/ui/<component-name>` in your page or route.

## Summary

| Do | Don't |
|---|---|
| Use a component from `src/components/ui/` | Hand-write a new UI component |
| Add missing primitives via `npx shadcn@latest add` | Build a primitive from raw `div`s/Tailwind |
| Compose shadcn components inline in pages | Create a custom wrapper component around a shadcn component |
| Use Tailwind utilities for layout between components | Write custom CSS or `<style>` blocks |
| Use `cn()` from `@/lib/utils` for conditional classes | Introduce another UI/component library |
